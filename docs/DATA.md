# Data

The paper evaluates on three public face-forgery datasets. This repository does not host or link
any of their data: request or download each one from its maintainers and follow their terms.

| Dataset | Where to get it | Used for |
| --- | --- | --- |
| FaceForensics++ (FF++) | request form at [github.com/ondyari/FaceForensics](https://github.com/ondyari/FaceForensics) | main corpus; record model and detectors are trained on its train split |
| DFDC | [ai.meta.com/datasets/dfdc](https://ai.meta.com/datasets/dfdc/) (also on [Kaggle](https://www.kaggle.com/c/deepfake-detection-challenge/data)) | second corpus and transfer target |
| Celeb-DF v2 | request form at [github.com/yuezunli/celeb-deepfakeforensics](https://github.com/yuezunli/celeb-deepfakeforensics) | third corpus and transfer target |

Only the **real** faces are enrolled (7,366 in the paper). Face-swap queries are generated by the
pipeline itself with [SimSwap](https://github.com/neuralchen/SimSwap) from the released images, so
you also need the SimSwap weights (see [`workflow/ENVIRONMENT.md`](../workflow/ENVIRONMENT.md)).

## Layout after frame extraction

Extract frames from the videos with `ffmpeg` (any sampling policy you like; the pipeline records
what exists). Arrange each dataset as

```
<frames_root>/
  train/  val/  test/                     # the dataset's own split
    <class>/                              # "Real" (or real, real_youtube, real_actors) or a manipulation name
      <video_id>/
        <frame>.png                       # .png, .jpg or .jpeg
```

Celeb-DF is re-split by source video inside the pipeline so no video crosses train/val/test; FF++
and DFDC keep their own protocol splits.

## Prepare and enroll

1. **Stage 0, one manifest per dataset** (columns `split,class,video_id,frame_path`):

   ```bash
   cd workflow
   python scripts/make_source_manifest.py <ffpp_frames_root>    <out>/ffpp_manifest.csv
   python scripts/make_source_manifest.py <dfdc_frames_root>    <out>/dfdc_manifest.csv
   python scripts/make_source_manifest.py <celebdf_frames_root> <out>/celebdf_manifest.csv
   ```

2. **Point the pipeline at the manifests and SimSwap**, then run every stage (manifest, face
   alignment, enrollment, queries, features, record model, integrity gate):

   ```bash
   cd ..                                       # back to the repository root
   pip install -e .
   cp config.example.yaml config.yaml          # set source_manifests.{ffpp,dfdc,celebdf} and simswap_root
   python workflow/scripts/preflight.py --require-gpu   # checks packages, weights and inputs
   workflow/run_workflow.sh --gpu 0            # resumable; --verify-only re-checks a finished root
   ```

   The same two steps are registry entries:
   `python -m doctor_trigger reproduce pipeline-stage0 frames_root=<...> out_csv=<...>` and
   `python -m doctor_trigger reproduce pipeline`.

Outputs stay under `workflow/` (released images, private records, queries, features). Stage details
and the record format are in [`workflow/WORKFLOW.md`](../workflow/WORKFLOW.md).
